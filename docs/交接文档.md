# 交接文档（运维 / 接手须知）

> 适用范围：CWFLY-WEB 拆分仓的**前端静态站 + Python 后端**生产环境交接。
> 原则：**服务器地址、账号口令、密钥、群号等敏感信息一律不在仓库内出现**。本文中 `<server>`、`<domain>`、`<group-id>` 等占位符请向运维负责人索取实际值（或查阅服务器上的 `/opt/cwfly/**/.env` 与运维登记表）。
> 相关文档：[`backend-py/deploy/PRODUCTION.md`](../backend-py/deploy/PRODUCTION.md)（后端生产手册，含性能基线与切换记录）、[`ARCHITECTURE.md`](ARCHITECTURE.md)、根 [`README.md`](../README.md)。

## 一、系统角色与仓库分工

| 角色 | 仓库 | 说明 |
|---|---|---|
| 前端站点 | **CWFLY-WEB/frontend**（本仓） | Vue 3 SPA，构建为静态文件由 Nginx 直出 |
| API / 业务后端 | **CWFLY-WEB/backend-py**（本仓） | Python 3.11 + FastAPI，PM2 托管在 `<server>`；Node/Express 后端已于 2026-10-31 下线并归档 |
| FSD 连飞服务器 | CWFLY-FSD | Python asyncio 实现；向 `whazzup.txt` 输出实时机组/管制快照 |
| 管制中心 | CWFLY-ATC | 独立子站（`atc.<domain>`），自有 Nginx vhost 与后端 |
| QQ 机器人 | CWFLY-BOT | OneBot 协议，负责群播报与监控告警通道 |
| 文档站 | CWFLY-DOCS | 对外文档站点 |

**数据流概要**：前端（浏览器）→ Nginx（静态直出 + 反向代理 `/api`、`/socket.io`、`/uploads`）→ FastAPI（`:3001`）→ MySQL / Redis；实时机组数据来自 FSD 输出的 `whazzup.txt`，由后端解析后提供接口与 Socket.IO 广播。

## 二、服务器角色与目录布局

> 以下为生产机现状（以 `PRODUCTION.md` 记录为准），服务器地址以 `<server>` 占位。

| 组件 | 位置 / 名称 | 说明 |
|---|---|---|
| 操作系统 / 面板 | Linux（宝塔面板 `/www/server/`），4 vCPU | Nginx、MySQL、Redis、PM2 均由面板/系统托管 |
| 前端静态根 | `/opt/cwfly/frontend/dist` | **Nginx 直接静态返回，不经后端进程** |
| 前端上一版备份 | `/opt/cwfly/frontend/dist.bak-<时间戳>` | 发布时自动生成，用于回滚 |
| Python API | `/opt/cwfly/backend-py`，PM2 名 **`cwfly-api-py`** | `uvicorn app.asgi:application --host 127.0.0.1 --port 3001 --workers 2`，HTTP + Socket.IO |
| 后台任务 | PM2 名 **`cwfly-worker-py`** | `python -m app.worker`（定时任务 / whazzup 轮询 / FSD 轮询 / 备份 / 天气预热），与 API 进程隔离 |
| 后端 venv | `/opt/cwfly/backend-py/.venv` | Python 3.11.9，依赖 `requirements.txt` |
| 后端环境变量 | `/opt/cwfly/backend-py/.env` | 同库同密钥，`PORT=3001`；**不提交、不打印到工单/群聊** |
| 上传目录 | `/opt/cwfly/backend-py/uploads` | 头像 / 海报 / 背景 / 会议资料；实体目录（勿删、勿整目录替换） |
| Node 后端（已下线） | 归档 `/opt/cwfly/backups/backend-node-final-<ts>.tar.gz`，原 `/opt/cwfly/backend` 已删除 | 仅应急回滚时解包使用 |
| Redis | `127.0.0.1:6379`（系统 systemd 自启） | Socket.IO 跨 worker 广播、天气共享缓存 `cwfly:weather:*`、PoW 令牌 `cwfly:pow:*` |
| MySQL / MariaDB | 本机 `127.0.0.1:3306` | 单库（`DATABASE_URL` 见 `.env`），表结构**沿用原 Node 库**，Alembic 仅 baseline |
| Nginx 站点配置 | `/www/server/panel/vhost/nginx/{api,atc,cwfly}.cwfly.conf.conf` | 宝塔面板管理；3 个站点：主站 / API / ATC |
| Nginx 全局配置 | `/www/server/nginx/conf/nginx.conf` | 已开启 `gzip_static on` + `open_file_cache` |
| 监控脚本 | `/opt/cwfly/cwfly-api-py-monitor.sh`（cron 每分钟），日志 `/opt/cwfly/monitor-api-py.log` | 5xx/ERROR 告警 + 自愈重启 + 日志轮转 |
| 自愈脚本 | `/opt/cwfly/ddos-hardening.sh`（cron 每分钟 `recover`） | 健康检查 `http://127.0.0.1:3001/health`，失败 `pm2 reload/restart cwfly-api-py` |
| 备份脚本 | `backend-py/scripts/db_backup.sh`（cron） | 数据库备份，env 路径指向 `/opt/cwfly/backend-py/.env` |
| 机器人健康检查 | `/opt/cwfly/bot/**` + `cwfly-bot-healthcheck.sh` | 与本项目前/后端无直接耦合 |

**PM2 纪律（重要）**：

- 只操作 `cwfly-api-py` / `cwfly-worker-py` 两个进程；
- **禁止 `pm2 restart all`** —— 会同时重启所有进程并掉线全部在线连飞用户；
- 变更后必须 `pm2 save`，否则服务器重启后进程不会自动拉起；
- `pm2 list` 中 Node 进程 `cwfly-api` 应**不存在**（已 `pm2 delete`）。

## 三、Nginx 站点要点

### 主站（`cwfly` vhost）

| location | 行为 |
|---|---|
| `/` | `root /opt/cwfly/frontend/dist`；`index index.html`；history 路由回退 `try_files $uri $uri/ /index.html` |
| `/assets/`、`/vendor/`、`/models/`、`/bg-home/`、`/airports/`、`/logo/` 等 | 静态直出；`/bg-home/` 长缓存 `Cache-Control: max-age=2592000`（30 天） |
| 旧 `.png` 背景兜底 | `location ~ ^/bg-home/.*\.png$` → **301 跳 `.webp`**（兼容旧缓存客户端，避免继续传 3.8MB 大图） |
| `/api` | `proxy_pass http://127.0.0.1:3001`（upstream `cwfly_api_pool`，keepalive 64） |
| `/socket.io` | `proxy_pass :3001`；必须 `proxy_http_version 1.1` + `Upgrade`/`Connection "upgrade"`，`proxy_read_timeout 600s` |
| `/uploads` | `proxy_pass :3001`（或指向上传目录），`client_max_body_size 25m` |
| 安全头 / CSP | 需允许 **`worker-src 'self' blob:;`**（PoW Worker 必需）、Mapbox / 高德 / OWM 相关域名（`connect-src`/`script-src`/`img-src`/`font-src`） |

### API 站点（`api` vhost）与 ATC 站点（`atc` vhost）

- 均由宝塔面板维护，`/api` 与 `/socket.io` 指向 `:3001`；灰度期的 `nginx-api-gray.conf`（`backend-py/deploy/`）仅作历史参考，Node 下线后不再需要双 upstream。
- 修改 vhost 流程：**备份 → 改 → `nginx -t` → `nginx -s reload`**；禁止直接 `restart nginx`（会短暂中断全部站点）。

### 证书与域名

- TLS 证书由面板统一申请/续期；到期前检查主站与 `api.` / `atc.` 子域是否同时续上。
- 域名：`www.<domain>`（主站，含裸域 `http://<domain>` 跳转）与 `api.<domain>` / `atc.<domain>`；CORS 白名单在 `backend-py/.env` 的 `CORS_ORIGIN`（生产需同时含 `https://www.<domain>` 与 `https://<domain>` 裸域，否则 Socket.IO 会因 origin 校验反复重连）。

## 四、前端发布流程

> 仓库内**没有**前端一键部署脚本，沿用「本地构建 → 上传 dist → Nginx 静态直出」流程。所有命令可直接复制，`<server>` 替换为服务器地址。

### 发布前检查

- [ ] `main` 分支代码已 review 合并，本地 `cd frontend && npm ci && npm run test && npm run lint && npm run build` 全绿
- [ ] 生产环境变量已就绪：构建时提供 `VITE_MAPBOX_TOKEN`（`.env.production`，不要提交仓库）；如用到雷达，另配 `VITE_OWM_KEY`
- [ ] 确认无数据库/后端变更需要同时发布（纯前端发布**不需要**重启 PM2）
- [ ] 记录发布时间与版本（`git log -1 --oneline`），便于回滚定位

### 发布命令

```bash
# 1) 本地构建（产物 frontend/dist/）
cd frontend && npm ci && npm run build

# 2) 打包上传
cd frontend && tar -czf /tmp/cwfly-frontend-dist.tgz -C dist .
scp /tmp/cwfly-frontend-dist.tgz root@<server>:/tmp/

# 3) 服务器：备份旧版 → 增量覆盖 → 校验 nginx
ssh root@<server> '
  set -e
  cd /opt/cwfly/frontend &&
  cp -a dist "dist.bak-$(date +%Y%m%d-%H%M%S)" &&
  tar -xzf /tmp/cwfly-frontend-dist.tgz -C dist &&
  nginx -t
'

# 4) 需要时 reload（纯静态资源替换通常无需 reload；改 vhost 才需要）
ssh root@<server> 'nginx -s reload'

# 5) 验证
curl -sI https://www.<domain>/ | head -n 5
curl -s -o /dev/null -w '%{http_code}\n' https://www.<domain>/api/auth/check-admin
```

### 发布纪律

1. **增量覆盖，不删旧资源**：新 `index.html` 引用新 hash 资源，但正在浏览的旧页面仍会请求旧 hash 文件；`rm -rf dist` 会导致在线用户 404/白屏。只允许定期清理「超过 30 天且确认无引用」的旧 `dist.bak-*`。
2. **静态资源带 hash 长缓存**；图片（`bg-home/` 等）替换要**改文件名**，不要原地覆盖，否则客户端 30 天内看不到新图。
3. **前端发布不重启后端**；后端发布只动 `cwfly-api-py`，见 `backend-py/deploy/deploy.sh`。
4. 发布后抽查：首页、登录、在线地图（2D/3D 切换）、管理后台用户页、深色主题。

### 前端回滚

```bash
ssh root@<server> '
  set -e
  cd /opt/cwfly/frontend &&
  mv dist "dist.failed-$(date +%Y%m%d-%H%M%S)" &&
  mv dist.bak-<要回滚到的时间戳> dist &&
  nginx -s reload
'
```

- 回滚目标选择：`ls -dt /opt/cwfly/frontend/dist.bak-* | head`。
- 回滚后验证同发布验证项；确认无误再清理失败的 `dist.failed-*`。
- 若问题来自 Nginx 配置：恢复 `/tmp/nginx-rollback-*` 或 `/www/server/panel/vhost/nginx/*.bak-*` 备份后 `nginx -t && nginx -s reload`。

## 五、后端发布 / 回滚（摘要）

完整手册见 [`backend-py/deploy/PRODUCTION.md`](../backend-py/deploy/PRODUCTION.md)。要点：

```bash
# 本地打包 → 上传 → 服务器执行（自动：停服→解包→保留 venv/.env→装依赖→编译→DB 自检→起服→健康检查→pm2 save）
tar -czf /tmp/backend-py.tgz --exclude='backend-py/.venv' --exclude='backend-py/logs' \
    --exclude='backend-py/uploads' --exclude='backend-py/backups' --exclude='backend-py/.env' backend-py
scp /tmp/backend-py.tgz root@<server>:/tmp/
scp backend-py/deploy/deploy.sh root@<server>:/tmp/
ssh root@<server> 'bash /tmp/deploy.sh'
```

- `deploy.sh` 会：停 `cwfly-api-py` → 暂存 uploads → 解包（保留 `.venv` / `.env`）→ `pip install` → `compileall` → DB 自检 → 启动 **API 2 worker + `cwfly-worker-py`** → 健康检查 `/health`、`/api/auth/check-admin`、`/whazzup.json` → `pm2 save` → 预压缩静态资源。
- 回滚到 Node：`bash /tmp/deploy.sh --rollback` **只做 nginx 恢复 + `pm2 start cwfly-api`**；由于 Node 源码已归档并从 `/opt/cwfly/backend` 删除，真正回滚前需先用 `/opt/cwfly/backups/backend-node-final-<ts>.tar.gz` 解包回 `/opt/cwfly/backend` 并确认其依赖可用。
- 数据库结构：**禁止 Alembic autogenerate**；新表/列手写 revision（幂等：`IF NOT EXISTS` / 查 `information_schema`），启动前 `alembic upgrade head`。

## 六、数据库与 Redis 依赖

### MySQL / MariaDB

- 单库，表名/列名沿用原 Node 项目（`User`、`FlightPlan`、`FlightTrack`、`LoginLog`、`IpBan`、`SystemConfig` 等 60+ 表）；Python 后端**不做表结构迁移**，只读写同库。
- 风险点：任何列类型/长度调整必须评估旧数据与 Node 兼容性；生产改库前必须备份。
- 备份：`backend-py/scripts/db_backup.sh`（cron），另可手动 `mysqldump`；恢复演练请在新库上做。

### Redis

| 用途 | Key / 说明 | 缺失影响 |
|---|---|---|
| Socket.IO 跨 worker 广播 | manager 连接 `SOCKETIO_REDIS_URL` | 多 worker 下在线人数/房间广播不一致 |
| 天气共享缓存 | `cwfly:weather:*`（TTL 180s，worker 每 40s 预热热门机场） | 自动回退内存缓存，接口变慢 |
| PoW 令牌 | `cwfly:pow:*`（Lua GET+DEL 原子防重放） | 自动回退进程内存，多 worker 下校验可能失败 |

- `SOCKETIO_REDIS_URL` 在 **API 与 worker 两个 PM2 进程都要设置**。
- Redis 不可用时后端有降级逻辑，但 **Socket.IO 多 worker 广播会退化**，需尽快恢复。

### 进程依赖关系

```
浏览器 ──> Nginx ──> :3001 cwfly-api-py (uvicorn ×2) ──> MySQL / Redis
                     cwfly-worker-py（定时/轮询/预热）──> MySQL / Redis / 外网 API
FSD ──> /opt/cwfly/fsd-py/whazzup.txt ──> worker 轮询解析 ──> 接口 / Socket.IO
```

## 八、已知限制与待办（交接重点）

### 已知限制

1. **Node 后端已下线**：生产只有 Python；`deploy.sh --rollback` 的 Node 回滚路径需先解包归档源码才可用。
2. **限流是进程内滑动窗口**：`uvicorn --workers 2` 下上限按进程计算；扩多实例必须换 Redis/MySQL 共享 store。
3. **前端无部署脚本 / 无 CI 自动发布**：发布靠人工按第四节执行；CI 只做 test/lint/build 校验，不自动上线。
4. **SDK Key 硬编码**：高德 Key/安全码在源码（`components/map/mapCore.js`、`views/Replay.vue`）；Mapbox/OWM 走构建期 env。修改 Key 需改代码或环境变量后**重新构建**。
5. **开发代理端口不一致**：`vite.config.js` 代理指向 `:3000`，Python 后端默认 `:3001`；本地联调需对齐（见根 README FAQ Q2）。
6. **测试与 lint 覆盖有限**：单测仅 `src/utils`，lint 仅 utils/composables/components；`views/` 未纳入。
7. **单体巨型页面**：`views/OnlineMap.vue` 仍在拆分中（已抽出 `components/map/*`、`composables/useAirport*.js`）；人员接手后优先完成拆分，避免并行改动冲突。
8. **实时通道窄**：socket 仅在线人数/列表；地图机组数据 5s 轮询，高频实时需求需扩展后端 sockets。
9. **论坛已外链**：`/forum*` 跳外部站，仓库内 `views/forum/*` 为历史遗留（未挂路由），清理前先确认无引用。
10. **无 CDN / 无 SSR**：首屏受服务器 RTT 影响；`bg-home`、`models` 依赖 Nginx 长缓存与预压缩（`gzip_static`）。

### 待办（建议优先级）

| 优先级 | 事项 |
|---|---|
| P0 | 完成 `OnlineMap.vue` 拆分收尾并回归（2D/3D、机场编辑、回放） |
| P0 | 把 `views/` 纳入 lint 并逐步清零告警；扩大单测覆盖（见 `docs/TESTING.md` 补测计划） |
| P1 | 高德 Key 迁移到环境变量 + 域名白名单，去掉源码硬编码 |
| P1 | 前端发布脚本化（构建→上传→备份→校验一键），减少手工误操作 |
| P1 | 统一开发代理端口（前端/后端/文档说明三处对齐） |
| P2 | 地图机组数据从 5s 轮询迁移到 Socket.IO 增量推送 |
| P2 | 引入 CDN / 对象存储承载 `bg-home`、`models` 等大静态资源 |
| P2 | 清理历史遗留：`views/forum/*`、未引用依赖（leaflet / chart.js）、`install_panel.sh` 等 |
| P3 | 补齐部署/回滚的自动化验证（发布后自动冒烟：首页、登录、地图、后台） |

### 常见故障速查

| 现象 | 优先排查 |
|---|---|
| 站点 502 / 无法访问 | `pm2 list`（API 是否在线）→ `curl :3001/health` → Nginx vhost 是否指回 `:3001` |
| 首页正常但接口 401/403 | token 过期（6h）→ 前端是否正常续签；`CORS_ORIGIN` 是否含裸域；风控/封禁是否命中 |
| 登录后地图/机组为空 | FSD `whazzup.txt` 是否更新；worker 进程是否存活；浏览器控制台是否报告 Mapbox Token 问题 |
| 在线人数不刷新 | Socket.IO 连接是否建立（Network `socket.io` 101）；Redis 是否可用；裸域 origin 是否被拒 |
| 发布后白屏 | `dist` 是否被整体替换（旧 hash 资源 404）→ 回滚或增量重发；`index.html` 与资源是否同批 |
| 服务器重启后服务消失 | 是否 `pm2 save`；`pm2 resurrect`；`systemctl status redis` |
| 磁盘满 | 清理 `dist.bak-*`、旧日志（`pm2 flush` 谨慎）、uploads 历史文件；检查备份目录 |
| 告警通知收不到 | OneBot 机器人与 `/opt/cwfly/bot/.env` 是否正常；`MONITOR_NO_NOTIFY` 是否误设 |
